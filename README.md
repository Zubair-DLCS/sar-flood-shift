## Why this matters

During a flood, people make decisions from water maps produced from satellite radar, because clouds block optical imagery for days. Those maps come from models trained on a handful of past events. When the model is deployed on a new river basin, a new season or a different processing chain, its accuracy can collapse. A map that is wrong *and confident* is worse than no map at all.

This repo asks two questions:

1. **How much does accuracy drop under realistic shift?**
   Three levels: seen countries → a held-out country (Bolivia) → a new event processed with a different SAR product (Sindh, 2022).
2. **Does the model's uncertainty rise when its accuracy falls?**
   In other words, can an operator trust the uncertainty map to tell them *where not to trust the water map*?

## What is in here

| Component | Choice |
|---|---|
| Data | [Sen1Floods11](https://github.com/cloudtostreet/Sen1Floods11) hand-labelled chips: 446 chips of 512×512 px at 10 m, VV+VH in dB, from 11 flood events. Official train/valid/test splits plus Bolivia held out entirely. |
| Model | U-Net (ResNet-34 encoder, ImageNet init, 2-channel input), masked BCE + Dice loss |
| Uncertainty | Single model · MC dropout (20 passes) · 5-member deep ensemble · ensemble + temperature scaling (fitted on validation) |
| Metrics | IoU, F1 · ECE (calibration) · AUROC of entropy for detecting pixel errors · risk–coverage curve / AURC · chip-level Spearman correlation between mean entropy and error |
| Case study | Sentinel-1 RTC from Microsoft Planetary Computer: a pre-event scene (June 2022) and a flood scene (late Aug–early Sep 2022), same relative orbit, over Dadu / Johi / Lake Manchar, Sindh. Outputs are a water map, a newly-flooded map and an entropy map as GeoTIFFs. |

## Run it

The easiest route is the Colab notebook ([`notebooks/run_all.ipynb`](notebooks/run_all.ipynb)), which does everything on a free T4 GPU. Or run each step locally:

```bash
pip install -r requirements.txt

python scripts/download_sen1floods11.py --out data/sen1floods11          # ~1 GB
python scripts/train.py    --data data/sen1floods11 --out runs/ensemble --members 5
python scripts/evaluate.py --data data/sen1floods11 --runs runs/ensemble --out results

python scripts/pakistan_case_study.py fetch   --out data/pakistan
python scripts/pakistan_case_study.py predict --runs runs/ensemble --data data/pakistan \
       --out results/pakistan --sen1floods11-metrics results/metrics.json
```

`bash scripts/smoke_test.sh` runs the whole pipeline on synthetic data in about a minute on CPU. Use it to check that the code works. It does not produce results.

**Optional ground truth for Sindh.** UNOSAT published satellite-derived flood extents for the 2022 Pakistan floods. Download one that covers the AOI and pass it with `--reference path/to/extent.shp`. The script then reports IoU against it, and checks whether entropy flags the model's real errors. Without it, Sindh is compared only with an Otsu threshold. That baseline is a sanity check, **not ground truth**.

## Where it breaks

_Look at `results/figures/worst_chips.png` and the Sindh entropy map, then describe what you actually see._ SAR water mapping is known to fail in these cases, so check each one:

- **Wind-roughened open water.** Waves scatter radar back toward the satellite, so water looks bright like land. The result is missed water.
- **Flooded vegetation and towns.** Double-bounce scattering *brightens* the signal, so flooding under crops or between buildings is missed. This matters in Sindh, where much of the flooding was in farmland.
- **Dry sand, smooth tarmac and radar shadow.** These are dark like water, which produces false water. Sindh's arid surfaces make this a real risk.
- **Product shift.** Training used GEE σ⁰ GRD; Sindh uses Planetary Computer γ⁰ RTC. The two differ by a few dB depending on incidence angle and terrain. Compare `--norm-mode per_image` against `global` to see how much of the drop comes from this alone.

Two questions to answer honestly in this section:
- **Does entropy flag these failures, or is the model confidently wrong?** Confident failure is the important finding, if it shows up.
- **Does disagreement with Otsu mean the model is wrong?** Not always. Otsu thresholds single pixels and is fooled by speckle, while the U-Net uses spatial context.
